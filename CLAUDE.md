# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Eva Companion: a React Native + Expo app for a **single dedicated iPhone** sitting on a desk in **landscape** — an always-on robot face for Eva (a chief-of-staff agent), with on-device speech both directions. Not for the App Store; iOS only; one device. The PRD phases: 1 device foundation (done), 2 wake word, 3 live Eva over Slack (done), 4 appliance hardening.

Beyond the PRD: Eva runs as a **local agent loop** (`src/agent/`) talking straight to the OpenAI chat API, which is the default brain, and as a **realtime session** (`src/realtime/`) over a WebSocket that is only alive while someone is talking. and, experimentally, as a **hermes brain** (`src/hermes/useHermes.ts`) where Eva's other half answers the spoken turn directly. All four are switchable from the dev overlay; Slack is still the only source of proactive pushes.

## Commands

```bash
npm run probe:brain           # hermes as the brain: latency, wire format, whether it takes client tools (pass case numbers to subset — each one is a live agent run)
npm run probe:vision          # which models accept images, and whether they ask before looking
npm run probe:realtime        # realtime wire format, first-token latency against chat, preamble rate
npm test                      # jest (pure face-math tests); npx jest src/face/__tests__/geometry.test.ts for one file
npx tsc --noEmit              # typecheck (TS 6 — @types globals are NOT auto-included; tests import from @jest/globals)
npx expo start --go           # run face in Expo Go / simulator (STT unavailable there by design)
npx expo start                # dev-client mode for the physical iPhone with the EAS dev build
eas build --profile development --platform ios   # rebuild native shell (only when native deps change)
```

## Architecture

The face is a **port of an approved design** (`Eva Face.dc.html` in the claude.ai/design project "Eva Face") — all magic numbers in `src/face/constants.ts` come from it. Don't invent new animation values; change the design first, then port.

Two layers, deliberately separated:

- **Pure math** (`src/face/geometry.ts`, `src/face/visemes.ts`): per-mode eye deformation `eyeGeo(side, t, mode, blinkT, yawnT)`, blink/yawn envelopes, viseme table, waveform amplitudes. No React imports. Unit-tested; marked `'worklet'` because they also run on the Reanimated UI thread. Keep them pure.
- **Rendering** (`src/face/Face.tsx`): Skia canvas. Continuous animation (eye transforms, glow blur, waveform) runs on the UI thread via `useFrameCallback` + derived values reading shared values (`clock`, `blinkT`, `yawnT`); discrete changes (mode, viseme swap every 112ms, colors) are React state. The blink/yawn scheduler lives inside the frame callback (idle only). Corner radii use CSS clamping semantics — `clampCorners` replicates browser border-radius overlap rules.

`src/face/FaceScreen.tsx` owns all state (mode, mouth output, color, side column, transcript) and wires the echo loop + dev controls. The dev overlay opens on **triple-tap top-left**.

The round contract (`src/round/`) is what keeps the three brains interchangeable: `ask(text) => Promise<AskResult>` plus `formatLatency`, and `speakableFromMrkdwn` (flattens both Slack mrkdwn and plain markdown for the ear). `useEcho` switches on `AskResult` and cannot tell which brain answered — which is why the realtime transport could be added without touching the speech layer at all. Don't reach back into `src/slack/` for these.

Local agent (`src/agent/`) — same pure/effectful split as everything else:
- `history.ts` is the policy and holds the interesting decisions: session-gap detection, token-budget compaction (`planCompaction` never splits a user/assistant pair; `applyCompaction` drops by *count* so turns arriving mid-summarization survive), and `buildRequest`'s message layout. That layout is load-bearing for cost: persona + remembered summaries go in one leading system message that stays byte-identical for the whole session, so a compaction rewriting the running-summary message doesn't invalidate the cached prefix. Prompt caching needs ≥1024 prefix tokens, so it starts paying a few turns in, not on turn one.
- `store.ts` deliberately uses expo-file-system rather than AsyncStorage: one JSON file per archived session under `<documents>/eva/memory/`, named by `sessionId()` so listing sorts chronologically. That's the unit a future exe.dev sync would push.
- `useAgent.ts` owns all timing: the mount-time gap archive, the 30s abort, and compaction fired *after* a reply is on its way to the speaker, never in the round's critical path.
- `persona.ts` is Eva's local system prompt. Voice rules are shared with `docs/eva-proactive-prompt.md` — change those together. The tool paragraph is local-only, and deliberately doesn't enumerate or count the tools (the specs are the authority, and web search is absent without a key). Its preamble rule is load-bearing, not cosmetic: that sentence is what the speaker plays during a tool gap.
- **The model is switchable at runtime** (dev overlay → BRAIN → Model cycles `MODEL_PRESETS`), and this matters behaviorally, not just for cost: the spoken preamble before a tool call is *model-dependent*. `gpt-5.4-mini` (the default) emits it 6/6; `gpt-4o-mini` and `o4-mini` emit it 0/6 and go silent through the gap, where `TOOL_LINES` has to cover. `npm run probe:tools` measures this in a second — reach for it before concluding anything about what "the model" will or won't do. Two API facts it also settled: `max_completion_tokens` is accepted by every family (`max_tokens` is rejected by gpt-5/o-series, so it is gone), and `reasoning_effort` is rejected outright alongside function tools. Model constants live in `models.ts`, not `config.ts`, because `scripts/` can't load AsyncStorage.
- **Model resolution is deliberately separate from credentials** — `resolveModel()`: overlay override → `EXPO_PUBLIC_OPENAI_MODEL` → `DEFAULT_MODEL`. `envAgentInput()` returns key *and* model together and bring-up prefers it wholesale, so anything persisted next to the credentials is unreachable whenever the env key is set. Don't re-merge them.
- `tools/` — clock, memory search, web search (Tavily). Two rules that are easy to break: the spec list is built **once at bring-up**, because specs sit inside OpenAI's cached prefix and a per-turn list would cost the discount `history.ts` is built around; and **a tool never throws** — failures come back as an error string the model can speak. A tool with no credentials is absent from the list entirely rather than present and failing. `searchMemories`/`formatResults`/`formatClock` are pure and tested; the I/O wrappers around them stay thin.
- Replies **stream**, so time-to-first-audio no longer scales with reply length: `openai.chatStream` (XHR, because RN's fetch can't stream a response body — and `onprogress` must be assigned *before* `send()` or RN delivers the body in one lump) → `sse.ts` → `sentences.ts` → `tts.speakStream` → one long-lived Kokoro stream. Two non-obvious constraints: `sentences.ts` exists for the *sanitizer*, not for Kokoro (which partitions natively) — `speakableFromMrkdwn` can't unwrap half a `**bold**` span, so flattening happens only at sentence boundaries; and Kokoro's `stopAutomatically` is decided at the moment the stream goes live, from whether all input has already arrived (see `runStream`) — it cannot be hoisted to a constant, because `Kokoro::stream()` assigns `stopOnEmptyBuffer_` from its own parameter as it starts, clobbering any earlier `streamStop(false)`. The system voice can't stream and buffers to completion instead.
- `useEcho` opens the speech stream **lazily on the first delta**, which is also how it decides the delivery path: a transport that can't stream (Slack) simply never calls `onDelta` and gets the old whole-utterance path. There's no capability flag by design. The invariant to preserve when touching `askEva`: every exit either settles the face or leaves an open `speech.current` whose drain callback will — a face wedged in `thinking` leaves the wake watcher suspended and the appliance deaf.
- **Tool rounds speak in one stream with a gap in it.** The model emits its preamble ("let me look that up") as ordinary content on the same response as the tool call, so it streams and speaks through the existing path; `AskOptions.onToolStart` then flushes the pending half-sentence and calls `speech.hold(true)`. That hold exists for one reason: `audioOut`'s stall watchdog re-arms at `remainingSeconds + heldSeconds + 5`, and without it a tool taking longer than that reads as a dead stream, settles the round, and re-opens the mic mid-answer. `hold` threads `useEcho → tts → kokoro → audioOut`; the system voice no-ops it. Note `stopAutomatically` is *not* a hazard here — `runStream` reads `inputFinished()`, and `end()` only fires when the whole ask resolves. Two consequences worth knowing: asides can't run while a stream is open (`speak()` calls `stopSpeaking()`, which would kill it), so the `TOOL_LINES` fallback only fires when the model skipped its preamble; and an open `speech.current` no longer proves the answer started, which is why `askEva` checks `spoken.current` before choosing silence over an apology.

The realtime brain (`src/realtime/`) — the same round contract over a socket that only exists while someone is talking. Text in, text out; STT and Kokoro are untouched. Mirrors `src/slack/`'s three-file split (`protocol.ts` pure, `socket.ts` injectable, `useRealtime.ts` React), and for the same reason commit `e0c64b0` established: nothing below the hook may import React or AsyncStorage, or `node scripts/probe-realtime.ts` cannot load it.
- **The win is latency, not tokens.** The whole conversation is billed on every response — measured at ~60 more input tokens per question, though **97% of it comes back cached**. What it buys is bandwidth and time to first word: 393-997ms against chat completions' 512-1982ms. Don't re-argue this as a cost saving; `npm run probe:realtime` re-measures both columns.
- **GA event names, not beta.** `modalities` became `output_modalities`, and `response.text.delta` became **`response.output_text.delta`**. A beta spelling does not error — it simply never fires, so the session connects, accepts a question, and stays silent. Tool specs are **flat** here, not nested under `function` as chat completions wants. The probe drives the shipped encoders rather than a copy, so it cannot keep passing after `protocol.ts` drifts.
- **Session is truth; the socket is a cache.** Any structural edit to `Session` — compaction, ending it, forgetting everything — *drops the socket* rather than reconciling. `flushSeed` re-reads from disk before seeding, because both local brains are mounted at once and each holds a copy of the same file. The mount-time gap archive belongs to `useAgent` **alone**: running it in both would summarize the same stale session twice and bill for it twice.
- **A cancelled response can still deliver a tool call** — `response.function_call_arguments.done` fires on cancelled and incomplete responses. So `askGen` gates `toolkit.run()` itself, not merely the history write, and a supersede sends `response.cancel` and *waits* for `response.done` before creating the next user item. On the chat path the XHR abort made this unreachable; here it is a live hazard.
- **The socket watchdog is holdable**, unlike Slack's. A spoken consent gate leaves it silent for ten seconds or more plus an iOS permission dialog — indistinguishable from a dead link. The same `gated()` that suspends the ask timeout suspends the watchdog, exactly as `speech.hold` suspends audioOut's.
- **It never reconnects on its own.** A drop mid-round fails the round out loud; silent recovery would also be a lie, since the server-side conversation is gone and a reconnected socket is not the one the round was speaking to. A socket death *during a tool call* is unrecoverable by construction — the `call_id` exists only in that conversation — so the round fails rather than replaying.
- Photos are named with a client-chosen item id at creation so they can be `conversation.item.delete`d when the round settles; an image item is otherwise re-billed on every later response, defeating the vision window's aging-out.
- The **summarizers stay on HTTP** and on `DEFAULT_MODEL`: realtime models do not serve chat completions at all.
- Lifecycle lives in `FaceScreen`, not here: dial on `onWake`, release on the existing `mode → idle` effect after a grace. That transition is *exact* — during a follow-up the face cycles pleased → listening → thinking → speaking and never reaches idle — so it is not a second copy of `conversation.ts`'s policy.
- `src/agent/spend.ts` reports token spend for **both** brains in the same units, per response rather than per round, because that is the unit the API bills. It prints the cache hit rate beside the running total: caching is best-effort, and a conversation whose hit rate collapses is being re-billed in full every turn.

Vision (`src/vision/`) — Eva can take a photo through the front camera and reason about it, gated on a **spoken** yes:
- The gate is machine-enforced, not a persona instruction. `camera_look` blocks mid tool-loop on `AskOptions.onConsent`, which `useEcho` implements because it owns the mic. Anything that is not an audible yes — silence, a garbled answer, a superseded round, a transport with no gate — is a no. `readConsent` is pure and tested, and a refusal beats an affirmative in the same breath ("no, don't do it" contains "do").
- **The stream is ended, not held.** `startMic` calls `stopSpeaking()`, which kills an open Kokoro stream, so the tool gap's usual `hold(true)` is not enough: the preamble is flushed, `end()`ed, and *drained* before the mic opens, and the answer arrives on a fresh stream (`openSpeech` reopens on the next delta). Two things make that safe — `openSpeech`'s one-shot `drain` redirect, so `end()` doesn't settle the round and open a follow-up mic on top of the consent one; and `clearRoundSpeech` *releasing* a parked drain rather than dropping it, since by then the ask timeout is suspended and nothing else would ever settle the round.
- `useEcho`'s mount-once `onEnd` routes every transcript into `askEva`, so the gate is checked **first** — undiverted, "yeah go ahead" starts a round that kills the one waiting on it. The gate runs inside the round it gates (`startMic` takes a round rather than claiming one); claiming a new epoch would supersede the ask.
- **The preamble is the consent question**, so persona.ts tells her to phrase it as one for the camera. That is model-dependent and measured — see the vision block in `models.ts`; `npm run probe:vision` re-measures it. When no preamble arrives the gate speaks `CONSENT_QUESTION` itself.
- Photos are referenced, never embedded: a `Turn` holds only `{id, caption}` and `buildRequest` takes a resolver. That is what keeps base64 out of everything `store.ts` writes — no filtering, by construction — and what makes an aged-out photo degrade to prose instead of vanishing. The window is two (`photos.ts`); evicted cache files are deleted.
- `useAgent.gated()` stops the 30s ask clock while a gate is open, for the same reason `speech.hold` suspends audioOut's stall watchdog: a human answering is not a hang.
- iOS permission is requested on the *first* call and before anything is spoken — a modal landing on an open mic eats the answer. It is deliberately not part of the spec-list decision, which is built once at bring-up from whether the native module loaded.

The hermes bridge (`src/hermes/`) — **two embodiments, one Eva.** The device owns every spoken turn; hermes-agent owns durable memory and anything that can't finish inside one. Eva reaches it by **errand**, never by waiting.
- **She can ask him to *do* things, not only to find them out.** `tell_other_half` rides the same queue, runner and delivery path as `ask_other_half`; what differs is the request (`actionRequest`, which says do it and report back in one sentence, and forbids describing an intention as an outcome), the line spoken on the way back, and a gate in front. Two failure modes are guarded explicitly and both are measured by `npm run probe:errand`/`probe:action`: the two tools shadowing each other, and the acknowledgement claiming the change is already done when it lands a minute later — `SENT` exists to say "do NOT say it is done".
- **Destructive means confirmed out loud; additive just goes.** Eva sets `changes_existing` per action and it arms `useEcho`'s existing consent gate — the camera's, generalized so `onConsent` takes a fallback question, because what is agreed to here is the action itself rather than one fixed lens. A missing flag is treated as destructive, the *opposite* of `needs_lookup`'s default next door: the two get the benefit of the doubt in opposite directions on purpose. Measured at 6/6 delegated with 6/6 correct flags on `gpt-5.4-mini`; the preamble is phrased as a question 2/3 of the time, and `readbackLine` covers the rest exactly as `CONSENT_QUESTION` covers the camera.
- **The outbox records; it does not replay.** `outbox.ts` writes one file per action on dispatch and deletes it on settle, so a file's existence *is* the pending state and `takeUnfinished` deletes what it returns — a lost action is reported at exactly one bring-up rather than every launch forever. Questions are not journalled at all. Re-sending would need de-duplication, de-duplication needs an idempotency key hermes does not promise, and a task added twice beats one she admits losing track of. This is also why `actionFailureLine` is not `failureLine` with different words: a question that failed did not happen, an action may have landed with only the report lost, so it says she doesn't know.
- **hermes is never on the critical path of a spoken turn.** `ask_other_half` hands over a question and **returns at once**; the round settles at local speed, Eva says she'll come back to him, and the answer arrives minutes later. Wanting to await a hermes answer inside a round is the bug, not the fix — it was measured at **88.7s**.
- **Delivery reuses the proactive queue.** An errand answer is a `ProactiveItem` and rides the same drain as Eva's unprompted Slack messages: backlog cap, wait for a quiet face, `announce()`. `threadTs` is nullable because anything not from Slack has no thread — pointing a follow-up at a synthetic one sends it nowhere silently. `deliveryLine` re-anchors to the question, since minutes have passed and an answer arriving naked is a non-sequitur.
- **There is no prefetch.** An earlier design polled a context bundle every 150s. First live measurement killed it: **325,546 hermes-side prompt tokens** per bundle, because it is a full agent run with tools. The receiving half survives — `bundle.ts` (parse/budget/render/age), `store.ts`, `buildRequest`'s parameter — waiting for hermes to *broadcast*; `useBundle.refresh()` is wired to the overlay button only, a person rather than a timer.
- **Eva sets `needs_lookup` per question**, because that flag is most of the wall-clock: a full agent run with calendar and task lookups versus an answer from memory. The errand request always asks hermes for brevity and low reasoning — the answer is read aloud in a room.
- The transport is not a transport. hermes' API server is OpenAI-compatible, so this is `openai.ts` with a different `baseUrl` and two `X-Hermes-*` headers — the only reason `BASE` became an option. XHR's `setRequestHeader` *appends* on a repeat, so the streaming path filters managed headers out of the caller's map; the `fetch` path can just spread.
- **Tool wording is load-bearing and measured.** `memory_search` shadowed `ask_other_half` — she searched her own notes, found nothing, and stopped. Drawing the line ("conversations at this desk" vs. his actual world, and *escalate on an empty result*) took delegation from 1/4 to 4/4. `npm run probe:errand` re-measures that, plus whether she repeats her preamble in the acknowledgement (0/4 at the time of writing). `npm run probe:hermes` measures the gateway itself.
- **If a bundle is present** it goes early in the message list, not late (`buildRequest`, most-stable-first: persona → summary → bundle core → bundle volatile → turns). Late placement is uncached on *every* turn; early costs only turns where it changed. The core carries no timestamp for the same reason — freshness renders from the device's own clock, so an unchanged bundle produces a byte-identical core.
- **Absent and empty are different, everywhere.** Every bundle section is `string[] | null`: `null` is "hermes never told us", `[]` is "there is nothing on". `parseBundle` returns `null` rather than a partial in all three failure cases, so there is no path from a bad fetch to an empty bundle. Proved itself on the first live run — Calendar was unreachable, hermes omitted the section and said why, and Eva says she can't see it rather than describing an empty afternoon.
- `persona.ts` cannot branch on any of this — it is the cached prefix and must stay byte-identical — so it is written to read correctly either way. Its inability is scoped hard to *acting*; a blanket "I can't" measurably suppresses tool use. The errand paragraph's "not a pause in the conversation" and "don't keep bringing it up" each guard a specific failure.
**The hermes brain (`src/hermes/useHermes.ts`) — experimental, on `spike/hermes-brain`.** The same round contract, answered by hermes instead of by a model the device drives. It inverts the sentence above: hermes owns the spoken turn too, and the device is reduced to Eva's face, ears and voice. Everything about it was measured by `npm run probe:brain`, and the measurements are in that script's header rather than here.
- **It sends no tools, no history and no persona**, and all three are findings rather than choices. The API server is an agent runtime, not an LLM proxy: client specs are accepted, silently ignored, and charged for (20,652 input tokens to be ignored). `X-Hermes-Session-Id` holds the transcript server-side — a second turn recalled the first with an empty `messages` array — so `history.ts`, its compaction and its cached-prefix layout are all unused here, and the server's copy is the only copy. hermes brings its own persona, about 20k tokens of it.
- **What that costs: `camera_look` and its spoken-consent gate cannot exist on this brain**, nor can the errand tools, which would have Eva sending herself an errand. There is also no consent gate in front of a destructive write, because hermes decides server-side whether to act. That is the property to weigh before making this the default.
- **hermes streams no preamble**, unlike the chat brain where the model's own "let me look that up" covers the gap. A lookup turn was 8.8s of silence and a memory turn 16.3s. `hermes.tool.progress` events are the only warning, which is why `sse.ts` now surfaces named events at all and why `progress.ts` exists; `useEcho`'s existing no-preamble branch then arms `TOOL_LINES`, and the tool names hermes reports (`skill_view`, `terminal`) are already keys in it.
- **The ask clock is an idle timeout, not a budget.** A hermes turn is a full agent run of unbounded length, so a flat deadline either kills good rounds or waits far too long on dead ones; progress frames make liveness observable instead.
- **Tokens here are latency, not cost** — hermes rides the OpenAI subscription rather than a per-token key. The ~20k uncached prefix is why a turn starts at ~2.1s rather than sub-second, and the 0% cache hit rate is expected, not a caching bug: the prefix being billed is hermes' own.
- `forgetAll` and `cycleModel` say what they can't do rather than quietly doing nothing — memory is server-side with `memory_write_api: false`, and the server ignores a bare `model` unless `direct_model_requests` is enabled.
- `brainSessionId`'s stamp duplicates `history.ts`'s `sessionId` on purpose: a runtime import there is extensionless, which node's ESM resolver won't follow, and every probe in `scripts/` reaches `envHermesConfig()` through `config.ts`.

- `hermes/` at the repo root is the Eva-back half (bundle schema, gathering skill, API server config), not device code. The bundle contract is inlined in `prompt.ts` too — change both in the same commit.

Speech (`src/speech/`):
- `stt.ts` lazy-requires `expo-speech-recognition` so Expo Go (no native module) still runs the face. **Privacy invariant: `requiresOnDeviceRecognition: true`, and refuse to listen rather than fall back to network recognition.** Note: the PRD's preferred `expo-speech-transcriber` was rejected — its realtime path never sets the on-device flag.
- `tts.ts` picks and persists one Enhanced-quality English system voice (Eva's canonical voice).
- `jitter.ts` (pure) is why audio no longer stutters mid-sentence. That was never a partitioning problem — Kokoro is fed whole sentences — but a starved buffer: `audioOut` used to start on the first synthesized chunk, so any slow patch of synthesis emptied the queue and the gap landed mid-word. A lead is built before playback and *rebuilt* after a dry queue rather than resuming on one chunk and starving again. `[audioOut] lead built in NNNms` and `[audioOut] underrun` are how `PREBUFFER_SECONDS` gets tuned against the device instead of guessed at.
- `earcon.ts` (pure) generates the two wake cues as PCM rather than shipping audio files — no asset, no loader, and no new native module, which would mean an EAS rebuild. Both are enveloped so they start and end on true silence; a blip cut square clicks. The "go ahead" cue plays *inside* `startMic`'s audio-session settle, because the recognizer is on-device and would otherwise transcribe our own cue. Both fire only on wake-initiated rounds — a follow-up reopens the mic every turn.
- **`onFlowing` threads `audioOut → kokoro → tts → useEcho → FaceScreen → Face`**, the reverse of how `hold` threads down. The mouth animated purely off `mode === 'speaking'`, which stays true across every silence *inside* a reply, so it mimed through synthesis gaps and through the whole of every tool call. `pickViseme` and `amp` take a `voicing` flag defaulting to true, so the system voice — which has no visibility inside an utterance — behaves exactly as before.
- `useEcho.ts` is the round choreographer: listen → thinking → speak. Without an `ask` handler it falls back to the Phase-1 echo (speak the transcript back); with one it asks whichever brain is selected and speaks the reply. `announce()` is the reverse direction — Eva speaking first.
- Policy lives in pure, unit-tested modules with no React, and all timing/side effects stay in the hooks: `conversation.ts` (follow-up window), `asides.ts` (filler cadence), `proactive.ts` (thread adoption + backlog for Eva-initiated messages). Follow that split when adding behavior.

## Constraints

- Orientation is locked landscape in `app.json`; keep-awake is on in `App.tsx`. Don't add portrait handling.
- Eye separation is fixed wide (300px gap) and the side column defaults to visible — both explicit product decisions; don't resurrect the toggles from the design doc.
- Native module changes (new Expo packages with native code) require a new EAS dev build on the dedicated iPhone; JS-only changes do not.
