# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Eva Companion: a React Native + Expo app for a **single dedicated iPhone** sitting on a desk in **landscape** — an always-on robot face for Eva (a chief-of-staff agent), with on-device speech both directions. Not for the App Store; iOS only; one device. The PRD phases: 1 device foundation (done), 2 wake word, 3 live Eva over Slack (done), 4 appliance hardening.

Beyond the PRD: Eva runs as a **local agent loop** (`src/agent/`) talking straight to the OpenAI chat API, which is the default brain, and as a **realtime session** (`src/realtime/`) over a WebSocket that is only alive while someone is talking, and, experimentally, as a **hermes brain** (`src/hermes/useHermes.ts`) where Eva's other half answers the spoken turn directly. All four are switchable from the dev overlay; Slack is still the only source of proactive pushes.

## Commands

```bash
npm run probe:vision          # which models accept images, and whether they ask before looking
npm run probe:hermes-vision   # whether hermes reads a photo, and asks with [[look]] before looking
npm run probe:realtime        # realtime wire format, first-token latency against chat, preamble rate
npm test                      # jest (pure face-math tests); npx jest src/face/__tests__/geometry.test.ts for one file
npx tsc --noEmit              # typecheck (TS 6 — @types globals are NOT auto-included; tests import from @jest/globals)
npx expo start --go           # run face in Expo Go / simulator (STT unavailable there by design)
eas build --profile preview --platform ios       # rebuild the desk iPhone's app (only when native deps change). Always preview — never `development` unless Michael explicitly asks
eas update --channel preview --environment preview   # ship JS-only changes to the preview build over the air
```

## Architecture

The face is a **port of an approved design** (`Eva Face.dc.html` in the claude.ai/design project "Eva Face") — all magic numbers in `src/face/constants.ts` come from it. Don't invent new animation values; change the design first, then port.

Two layers, deliberately separated:

- **Pure math** (`src/face/geometry.ts`, `src/face/visemes.ts`): per-mode eye deformation `eyeGeo(side, t, mode, blinkT, yawnT)`, blink/yawn envelopes, viseme table, waveform amplitudes. No React imports. Unit-tested; marked `'worklet'` because they also run on the Reanimated UI thread. Keep them pure.
- **Rendering** (`src/face/Face.tsx`): Skia canvas. Continuous animation (eye transforms, glow blur, waveform) runs on the UI thread via `useFrameCallback` + derived values reading shared values (`clock`, `blinkT`, `yawnT`); discrete changes (mode, viseme swap every 112ms, colors) are React state. The blink/yawn scheduler lives inside the frame callback (idle only). Corner radii use CSS clamping semantics — `clampCorners` replicates browser border-radius overlap rules.

`src/face/FaceScreen.tsx` owns all state (mode, mouth output, color, side column, transcript) and wires the echo loop + dev controls. The dev overlay opens on **triple-tap top-left**.

The round contract (`src/round/`) is what keeps the three brains interchangeable: `ask(text) => Promise<AskResult>` plus `formatLatency`, and `speakableFromMrkdwn` (flattens both Slack mrkdwn and plain markdown for the ear). `useEcho` switches on `AskResult` and cannot tell which brain answered — which is why the realtime transport could be added without touching the speech layer at all. Don't reach back into `src/slack/` for these.

Local agent (`src/agent/`) — same pure/effectful split as everything else:
- `history.ts` is the policy and holds the interesting decisions: session-gap detection, token-budget compaction (`planCompaction` never splits a user/assistant pair; `applyCompaction` drops by *count* so turns arriving mid-summarization survive), and `buildRequest`'s message layout. That layout is load-bearing for cost: persona + remembered summaries go in one leading system message that stays byte-identical for the whole session, so a compaction rewriting the running-summary message doesn't invalidate the cached prefix. Prompt caching needs ≥1024 prefix tokens, so it starts paying a few turns in, not on turn one.
- `store.ts` deliberately uses expo-file-system rather than AsyncStorage: one JSON file per archived session under `<documents>/eva/memory/`, named by `sessionId()` so listing sorts chronologically. That's the unit a future exe.dev sync would push.
- `useAgent.ts` owns all timing: the mount-time gap archive, the 30s abort, and compaction fired *after* a reply is on its way to the speaker, never in the round's critical path.
- `persona.ts` is Eva's local system prompt. Voice rules are shared with `docs/eva-proactive-prompt.md` — change those together. The tool paragraph is local-only, and deliberately doesn't enumerate or count the tools (the specs are the authority, and web search is absent without a key). Its preamble rule is load-bearing, not cosmetic: that sentence is what the speaker plays during a tool gap.
- **The model is switchable at runtime** (dev overlay → BRAIN → Model cycles `MODEL_PRESETS`), and this matters behaviorally, not just for cost: the spoken preamble before a tool call is *model-dependent*. `gpt-5.4-mini` (the default) emits it 6/6; `gpt-4o-mini` and `o4-mini` emit it 0/6 and go silent through the gap, where `TOOL_LINES` has to cover. `npm run probe:tools` measures this in a second — reach for it before concluding anything about what "the model" will or won't do. Two API facts it also settled: `max_completion_tokens` is accepted by every family (`max_tokens` is rejected by gpt-5/o-series, so it is gone), and `reasoning_effort` is rejected outright alongside function tools. Model constants live in `models.ts`, not `config.ts`, because `scripts/` can't load AsyncStorage.
- **Model resolution is deliberately separate from credentials** — `resolveModel()`: overlay override → `EXPO_PUBLIC_OPENAI_MODEL` → `DEFAULT_MODEL`. `envAgentInput()` returns key *and* model together and bring-up prefers it wholesale, so anything persisted next to the credentials is unreachable whenever the env key is set. Don't re-merge them.
- `tools/` — clock, memory search, web search (Tavily). Two rules that are easy to break: the spec list is built **once at bring-up**, because specs sit inside OpenAI's cached prefix and a per-turn list would cost the discount `history.ts` is built around; and **a tool never throws** — failures come back as an error string the model can speak. A tool with no credentials is absent from the list entirely rather than present and failing. `searchMemories`/`formatResults`/`formatClock` are pure and tested; the I/O wrappers around them stay thin.
- Replies **stream**, so time-to-first-audio no longer scales with reply length: `openai.chatStream` (XHR, because RN's fetch can't stream a response body — and `onprogress` must be assigned *before* `send()` or RN delivers the body in one lump) → `sse.ts` → `sentences.ts` → `tts.speakStream` → one long-lived Kokoro stream. Two non-obvious constraints: `sentences.ts` exists for the *sanitizer*, not for Kokoro (which partitions natively) — `speakableFromMrkdwn` can't unwrap half a `**bold**` span, so flattening happens only at sentence boundaries; and Kokoro's `stopAutomatically` is decided at the moment the stream goes live, from whether all input has already arrived (see `runStream`) — it cannot be hoisted to a constant, because `Kokoro::stream()` assigns `stopOnEmptyBuffer_` from its own parameter as it starts, clobbering any earlier `streamStop(false)`. The system voice can't stream and buffers to completion instead.
- `useEcho` opens the speech stream **lazily on the first delta**, which is also how it decides the delivery path: a transport that can't stream (Slack) simply never calls `onDelta` and gets the old whole-utterance path. There's no capability flag by design. The invariant to preserve when touching `askEva`: every exit either settles the face or leaves an open `speech.current` whose drain callback will — a face wedged in `thinking` leaves the wake watcher suspended and the appliance deaf.
- **Tool rounds speak in one stream with a gap in it.** The model emits its preamble ("let me look that up") as ordinary content on the same response as the tool call, so it streams and speaks through the existing path; `AskOptions.onToolStart` then flushes the pending half-sentence and calls `speech.hold(true)`. That hold exists for one reason: `audioOut`'s stall watchdog re-arms at `remainingSeconds + heldSeconds + 5`, and without it a tool taking longer than that reads as a dead stream, settles the round, and re-opens the mic mid-answer. `hold` threads `useEcho → tts → kokoro → audioOut`; the system voice no-ops it. Note `stopAutomatically` is *not* a hazard here — `runStream` reads `inputFinished()`, and `end()` only fires when the whole ask resolves. Two consequences worth knowing: asides can't run while a stream is open (`speak()` calls `stopSpeaking()`, which would kill it), so the `TOOL_LINES` fallback only fires when the model skipped its preamble; and an open `speech.current` no longer proves the answer started, which is why `askEva` checks `spoken.current` before choosing silence over an apology.

The realtime brain (`src/realtime/`) — the same round contract over a socket that only exists while someone is talking. Text in, text out; STT and Kokoro are untouched. Mirrors `src/slack/`'s three-file split (`protocol.ts` pure, `socket.ts` injectable, `useRealtime.ts` React), and for the same reason commit `e0c64b0` established: nothing below the hook may import React or AsyncStorage, or `node scripts/probe-realtime.ts` cannot load it.
- **The win is latency, not tokens.** The whole conversation is billed on every response — measured at ~60 more input tokens per question, though **97% of it comes back cached**. What it buys is bandwidth and time to first word: 393-997ms against chat completions' 512-1982ms. Don't re-argue this as a cost saving; `npm run probe:realtime` re-measures both columns.
- **GA event names, not beta.** `modalities` became `output_modalities`, and `response.text.delta` became **`response.output_text.delta`**. A beta spelling does not error — it simply never fires, so the session connects, accepts a question, and stays silent. Tool specs are **flat** here, not nested under `function` as chat completions wants. The probe drives the shipped encoders rather than a copy, so it cannot keep passing after `protocol.ts` drifts.
- **Session is truth; the socket is a cache.** Any structural edit to `Session` — compaction, ending it, forgetting everything — *drops the socket* rather than reconciling. `flushSeed` re-reads from disk before seeding, because both local brains are mounted at once and each holds a copy of the same file. The mount-time gap archive belongs to `useAgent` **alone**: running it in both would summarize the same stale session twice and bill for it twice.
- **A cancelled response can still deliver a tool call** — `response.function_call_arguments.done` fires on cancelled and incomplete responses. So `askGen` gates `toolkit.run()` itself, not merely the history write, and a supersede sends `response.cancel` and *waits* for `response.done` before creating the next user item. On the chat path the XHR abort made this unreachable; here it is a live hazard.
- **The socket watchdog is holdable**, unlike Slack's. A spoken consent gate leaves it silent for ten seconds or more plus an iOS permission dialog — indistinguishable from a dead link. The same `gated()` that suspends the ask timeout suspends the watchdog, exactly as `speech.hold` suspends audioOut's.
- **It never reconnects on its own.** A drop mid-round fails the round out loud; silent recovery would also be a lie, since the server-side conversation is gone and a reconnected socket is not the one the round was speaking to. A socket death *during a tool call* is unrecoverable by construction — the `call_id` exists only in that conversation — so the round fails rather than replaying.
- Photos are named with a client-chosen item id at creation so they can be `conversation.item.delete`d when the round settles; an image item is otherwise re-billed on every later response, defeating the vision window's aging-out.
- The **summarizers stay on HTTP** and on `DEFAULT_MODEL`: realtime models do not serve chat completions at all.
- Lifecycle lives in `FaceScreen`, not here: dial on `onWake`, release on the existing `mode → idle` effect after a grace. That transition is *exact* — during a follow-up the face cycles resting → listening → thinking → speaking and never reaches idle — so it is not a second copy of `conversation.ts`'s policy.
- `src/agent/spend.ts` reports token spend for **both** brains in the same units, per response rather than per round, because that is the unit the API bills. It prints the cache hit rate beside the running total: caching is best-effort, and a conversation whose hit rate collapses is being re-billed in full every turn.

Vision (`src/vision/`) — Eva can take a photo through the front camera and reason about it, gated on a **spoken** yes:
- The gate is machine-enforced, not a persona instruction. `camera_look` blocks mid tool-loop on `AskOptions.onConsent`, which `useEcho` implements because it owns the mic. Anything that is not an audible yes — silence, a garbled answer, a superseded round, a transport with no gate — is a no. `readConsent` is pure and tested, and a refusal beats an affirmative in the same breath ("no, don't do it" contains "do").
- **The stream is ended, not held.** `startMic` calls `stopSpeaking()`, which kills an open Kokoro stream, so the tool gap's usual `hold(true)` is not enough: the preamble is flushed, `end()`ed, and *drained* before the mic opens, and the answer arrives on a fresh stream (`openSpeech` reopens on the next delta). Two things make that safe — `openSpeech`'s one-shot `drain` redirect, so `end()` doesn't settle the round and open a follow-up mic on top of the consent one; and `clearRoundSpeech` *releasing* a parked drain rather than dropping it, since by then the ask timeout is suspended and nothing else would ever settle the round.
- `useEcho`'s mount-once `onEnd` routes every transcript into `askEva`, so the gate is checked **first** — undiverted, "yeah go ahead" starts a round that kills the one waiting on it. The gate runs inside the round it gates (`startMic` takes a round rather than claiming one); claiming a new epoch would supersede the ask.
- **The preamble is the consent question**, so persona.ts tells her to phrase it as one for the camera. That is model-dependent and measured — see the vision block in `models.ts`; `npm run probe:vision` re-measures it. When no preamble arrives the gate speaks `CONSENT_QUESTION` itself.
- Photos are referenced, never embedded: a `Turn` holds only `{id, caption}` and `buildRequest` takes a resolver. That is what keeps base64 out of everything `store.ts` writes — no filtering, by construction — and what makes an aged-out photo degrade to prose instead of vanishing. The window is two (`photos.ts`); evicted cache files are deleted.
- `useAgent.gated()` stops the 30s ask clock while a gate is open, for the same reason `speech.hold` suspends audioOut's stall watchdog: a human answering is not a hang.
- iOS permission is requested on the *first* call and before anything is spoken — a modal landing on an open mic eats the answer. It is deliberately not part of the spec-list decision, which is built once at bring-up from whether the native module loaded.
- **hermes asks with `[[look]]`, never a tool** (ASC-43). hermes can't call `camera_look` (client tools are ignored on its server), so it ends a one-line consent question with the token and the device runs the *same* gate on its behalf: `useHermes.lookThenAnswer` mirrors `runCameraLook` step for step, then sends the photo as the next turn on the same transcript (`look.ts`'s `photoContent`, which restates the room rules — read nothing sensitive aloud, store nothing). Three entry points, one function: a hermes-brain reply (inside `ask`, the question is already streaming), a Slack-brain reply (`withLook` in FaceScreen), and a Slack push (`ProactiveItem.look`, delivered by `announce(text, run)`, which hands the round to `askEva` so the announcement streams as the "preamble" the gate drains). Slack can't carry a photo, so both Slack routes answer over the API server and quote the question, since the hermes answering is not the one that asked. Every no-photo outcome (refusal, iOS denial, failed shutter, no camera) is a local line spoken at once; a refusal is also prefixed to hermes' *next* turn as `DECLINED_NOTE` rather than spending a turn on it. The rule rides in `DESK_PREAMBLE` for the hermes brain and in `hermes/skills/eva-desk-camera/` for Slack; `npm run probe:hermes-vision` measures both that hermes reads the image (a solid colour it must name) and its token hit rate.
- **The face shows the lens is live.** `CameraBadge` sits on the face, not only in the side column (which can be off), for exactly as long as the viewfinder is mounted — every route above, local or hermes, goes through `showPreview`/`hidePreview`, so there is one signal and no way to open the lens without it.
- **The SAW thumbnail expires** (ASC-50): it fades out `THUMBNAIL_AFTER_REPLY_MS` after the face leaves `speaking` post-capture, and never stays past `THUMBNAIL_MAX_MS` from capture (`thumbnail.ts`, pure and tested). Anyone in the room can see it. Only the display goes; the photo stays in the window for follow-ups.

Location (`src/location/`; ASC-44) — Eva knows which **town** she is in, and nothing finer:
- **A setting, not a stream.** The phone lives on one desk, so the town is read once (the overlay's **Set location**, or the first `where_am_i` with nothing stored), and only its name is stored (`eva.place.v1`). Coordinates exist only inside `locate.ts`'s `readPlace` and go straight into the geocoder; `placeName` (pure, tested) reads town-and-above fields only, never street, number or the geocoder's `name`. `Accuracy.Lowest` on purpose.
- **No spoken ask — unlike the camera.** Michael's decision (Nov 27): Eva and hermes may read it freely, and iOS permission is the only gate. Don't put it behind `onConsent` by analogy with `camera_look`.
- **hermes asks with `[[location]]`**, answered exactly like `[[battery]]` (ASC-45): `asksForLocation` in `directives.ts`, `receive` reports `locationRequest`, and FaceScreen posts `locationReply` back with `useSlack.tell` — nothing spoken, no round on the face. With no town stored it reads only if iOS *already* allows it (`hasPermission`, never `ensurePermission`): the dialog could land on an empty room, the same reason the light meter skips it. Skill: `hermes/skills/eva-desk-location/`.
- `expo-location` is a native module: the first build carrying it needs an EAS build, and it is required lazily so an older build just has no `where_am_i`.

The hermes bridge (`src/hermes/`) — **two embodiments, one Eva.** The device owns every spoken turn; hermes-agent owns durable memory and anything that can't finish inside one. Eva reaches it by **errand**, never by waiting.
- **She can ask him to *do* things, not only to find them out.** `tell_other_half` rides the same queue, runner and delivery path as `ask_other_half`; what differs is the request (`actionRequest`, which says do it and report back in one sentence, and forbids describing an intention as an outcome), the line spoken on the way back, and a gate in front. Two failure modes are guarded explicitly and both are measured by `npm run probe:errand`/`probe:action`: the two tools shadowing each other, and the acknowledgement claiming the change is already done when it lands a minute later — `SENT` exists to say "do NOT say it is done".
- **Destructive means confirmed out loud; additive just goes.** Eva sets `changes_existing` per action and it arms `useEcho`'s existing consent gate — the camera's, generalized so `onConsent` takes a fallback question, because what is agreed to here is the action itself rather than one fixed lens. A missing flag is treated as destructive, the *opposite* of `needs_lookup`'s default next door: the two get the benefit of the doubt in opposite directions on purpose. Measured at 6/6 delegated with 6/6 correct flags on `gpt-5.4-mini`; the preamble is phrased as a question 2/3 of the time, and `readbackLine` covers the rest exactly as `CONSENT_QUESTION` covers the camera.
- **The outbox records; it does not replay.** `outbox.ts` writes one file per action on dispatch and deletes it on settle, so a file's existence *is* the pending state and `takeUnfinished` deletes what it returns — a lost action is reported at exactly one bring-up rather than every launch forever. Questions are not journalled at all. Re-sending would need de-duplication, de-duplication needs an idempotency key hermes does not promise, and a task added twice beats one she admits losing track of. This is also why `actionFailureLine` is not `failureLine` with different words: a question that failed did not happen, an action may have landed with only the report lost, so it says she doesn't know.
- **hermes is never on the critical path of a spoken turn.** `ask_other_half` hands over a question and **returns at once**; the round settles at local speed, Eva says she'll come back to him, and the answer arrives minutes later. Wanting to await a hermes answer inside a round is the bug, not the fix — it was measured at **88.7s**.
- **Delivery reuses the proactive queue.** An errand answer is a `ProactiveItem` and rides the same drain as Eva's unprompted Slack messages: backlog cap, wait for a quiet face, `announce()`. `threadTs` is nullable because anything not from Slack has no thread — pointing a follow-up at a synthetic one sends it nowhere silently. `deliveryLine` re-anchors to the question, since minutes have passed and an answer arriving naked is a non-sequitur.
- **There is no prefetch, and no context bundle.** An earlier design polled a context bundle every 150s. First live measurement killed it: **325,546 hermes-side prompt tokens** per bundle, because it is a full agent run with tools. Its receiving half lingered behind an overlay button and was removed in ASC-51, along with the side column's "stale" / "out of sync" label that aged it — `git show bf71277:src/hermes/bundle.ts` if hermes ever broadcasts one. Eva reaches hermes only by errand (or as the hermes brain).
- **Eva sets `needs_lookup` per question**, because that flag is most of the wall-clock: a full agent run with calendar and task lookups versus an answer from memory. The errand request always asks hermes for brevity and low reasoning — the answer is read aloud in a room.
- The transport is not a transport. hermes' API server is OpenAI-compatible, so this is `openai.ts` with a different `baseUrl` and two `X-Hermes-*` headers — the only reason `BASE` became an option. XHR's `setRequestHeader` *appends* on a repeat, so the streaming path filters managed headers out of the caller's map; the `fetch` path can just spread.
- **Tool wording is load-bearing and measured.** `memory_search` shadowed `ask_other_half` — she searched her own notes, found nothing, and stopped. Drawing the line ("conversations at this desk" vs. his actual world, and *escalate on an empty result*) took delegation from 1/4 to 4/4. `npm run probe:errand` re-measures that, plus whether she repeats her preamble in the acknowledgement (0/4 at the time of writing). `npm run probe:hermes` measures the gateway itself.
- `persona.ts` is the cached prefix and must stay byte-identical, so it cannot branch on whether hermes is configured. Its inability is scoped hard to *acting*; a blanket "I can't" measurably suppresses tool use. The errand paragraph's "not a pause in the conversation" and "don't keep bringing it up" each guard a specific failure.

**The hermes brain (`src/hermes/useHermes.ts`) — experimental, on `spike/hermes-brain`.** The same round contract, answered by hermes instead of by a model the device drives. It inverts the sentence above: hermes owns the spoken turn too, and the device is reduced to Eva's face, ears and voice. Everything about it was measured by a since-removed probe; its header holds the full measurements at `git show 401fe07:scripts/probe-hermes-brain.ts`.
- **It sends no tools, no history and no persona**, and all three are findings rather than choices. The API server is an agent runtime, not an LLM proxy: client specs are accepted, silently ignored, and charged for (20,652 input tokens to be ignored). `X-Hermes-Session-Id` holds the transcript server-side — a second turn recalled the first with an empty `messages` array — so `history.ts`, its compaction and its cached-prefix layout are all unused here, and the server's copy is the only copy. hermes brings its own persona, about 20k tokens of it.
- **What that costs: `camera_look` cannot exist on this brain**, nor can the errand tools, which would have Eva sending herself an errand. The camera comes back another way — see `[[look]]` below — but there is still no consent gate in front of a destructive write, because hermes decides server-side whether to act. That is the property to weigh before making this the default.
- **hermes streams no preamble**, unlike the chat brain where the model's own "let me look that up" covers the gap. A lookup turn was 8.8s of silence and a memory turn 16.3s. `hermes.tool.progress` events are the only warning, which is why `sse.ts` now surfaces named events at all and why `progress.ts` exists; `useEcho`'s existing no-preamble branch then arms `TOOL_LINES`, and the tool names hermes reports (`skill_view`, `terminal`) are already keys in it.
- **The ask clock is an idle timeout, not a budget.** A hermes turn is a full agent run of unbounded length, so a flat deadline either kills good rounds or waits far too long on dead ones; progress frames make liveness observable instead.
- **Tokens here are latency, not cost** — hermes rides the OpenAI subscription rather than a per-token key. The ~20k uncached prefix is why a turn starts at ~2.1s rather than sub-second, and the 0% cache hit rate is expected, not a caching bug: the prefix being billed is hermes' own.
- `forgetAll` and `cycleModel` say what they can't do rather than quietly doing nothing — memory is server-side with `memory_write_api: false`, and the server ignores a bare `model` unless `direct_model_requests` is enabled.
- `brainSessionId`'s stamp duplicates `history.ts`'s `sessionId` on purpose: a runtime import there is extensionless, which node's ESM resolver won't follow, and every probe in `scripts/` reaches `envHermesConfig()` through `config.ts`.

- `hermes/` at the repo root is the Eva-back half (desk skills, API server config), not device code.

Speech (`src/speech/`):
- `stt.ts` lazy-requires `expo-speech-recognition` so Expo Go (no native module) still runs the face. **Privacy invariant: `requiresOnDeviceRecognition: true`, and refuse to listen rather than fall back to network recognition.** Note: the PRD's preferred `expo-speech-transcriber` was rejected — its realtime path never sets the on-device flag.
- `wakeword.ts` (pure) decides what wakes her: a greeting (hey/hi/hello/hiya) then an Eva-like word, scanned across **every** recognizer alternative, not just the top guess — in a noisy room the right words are often the runner-up (ASC-37). A bare "Eva" never wakes her. What sounded like an attempt but didn't match is a *near-miss*, logged once per recognizer session at its end (an interim "hey ever" is often corrected a moment later) and shown in the overlay; that log is the evidence for tuning, and for whether ASC-39's dedicated wake engine is worth a rebuild. The overlay's **Noise filter** passes `iosVoiceProcessingEnabled` to both listen profiles — already in the native build, off by default because it can lower speaker volume.
- `tts.ts` picks and persists one Enhanced-quality English system voice (Eva's canonical voice).
- `jitter.ts` (pure) is why audio no longer stutters mid-sentence. That was never a partitioning problem — Kokoro is fed whole sentences — but a starved buffer: `audioOut` used to start on the first synthesized chunk, so any slow patch of synthesis emptied the queue and the gap landed mid-word. A lead is built before playback and *rebuilt* after a dry queue rather than resuming on one chunk and starving again. `[audioOut] lead built in NNNms` and `[audioOut] underrun` are how `PREBUFFER_SECONDS` gets tuned against the device instead of guessed at.
- `earcon.ts` (pure) generates the two wake cues as PCM rather than shipping audio files — no asset, no loader, and no new native module, which would mean an EAS rebuild. Both are enveloped so they start and end on true silence; a blip cut square clicks. The "go ahead" cue plays *inside* `startMic`'s audio-session settle, because the recognizer is on-device and would otherwise transcribe our own cue. Both fire only on wake-initiated rounds — a follow-up reopens the mic every turn.
- **The mouth follows the audio, not a loop** (ASC-53). Kokoro yields PCM with no phoneme timings, so `face/lipsync.ts` (pure, tested) classifies each 50ms of every chunk into a viseme from loudness, zero-crossing rate and two spectral-centroid estimates (the second, on the differenced signal, sees F2 — what separates ee from oo), and builds a timeline of when each chunk becomes audible *at scheduling time*, not from the buffer-ended event, which would land every chunk late by the bridge. audioOut publishes it to `speech/mouth.ts`, a module slot the Mouth polls — not React state threaded through FaceScreen, which would re-render the screen 20×/s. Thresholds were calibrated against macOS `say` rendered at 24 kHz. The system voice has no visible PCM, so it keeps the design's 112ms `SEQ` loop.
- **`onFlowing` threads `audioOut → kokoro → tts → useEcho → FaceScreen → Face`**, the reverse of how `hold` threads down. The mouth animated purely off `mode === 'speaking'`, which stays true across every silence *inside* a reply, so it mimed through synthesis gaps and through the whole of every tool call. `pickViseme` and `amp` take a `voicing` flag defaulting to true, so the system voice — which has no visibility inside an utterance — behaves exactly as before.
- `useEcho.ts` is the round choreographer: listen → thinking → speak. Without an `ask` handler it falls back to the Phase-1 echo (speak the transcript back); with one it asks whichever brain is selected and speaks the reply. `announce()` is the reverse direction — Eva speaking first.
- Policy lives in pure, unit-tested modules with no React, and all timing/side effects stay in the hooks: `conversation.ts` (follow-up window), `asides.ts` (filler cadence), `proactive.ts` (thread adoption + backlog for Eva-initiated messages). Follow that split when adding behavior.

Night sleep (`src/face/sleep.ts`, `useSleep.ts`, `brightness.ts`; ASC-33) — from 22:00 to 06:00 (`SLEEPY_START/END_HOUR`, also the yawning window) the screen dims, and after ten quiet minutes of night she looks asleep and dims further:
- **Asleep is a blend, not a mode.** `eyeGeo`'s `sleepK` pulls whatever the mode draws toward the asleep pose, and the face stays `'idle'` — the wake watcher only listens while it is, so a sleep mode would have made her deaf at night. The pose is the yawn's nearly-shut hold, centred, breathing on idle's glow pulse; it isn't in the design file yet, but every value is derived from the yawn's (see `constants.ts`), so it can be folded in as-is.
- **Anything happening wakes her**: a round (wake word, a proactive message, an errand answer), the dev overlay, or a touch anywhere (`onTouchStart` on the root, which doesn't consume it). She stays bright a minute after, then dims, then dozes off. Quiet counts only from 22:00, so she always dims before she sleeps. `sleep.ts` is pure and tested; the hook owns the clock.
- **Brightness is `expo-brightness`, a native module** — the first build to carry it needs an EAS build (the fingerprint runtime policy won't send this to an older binary anyway). It is required lazily like `stt.ts`'s recognizer, so a build without it still sleeps, just undimmed. iOS keeps an app-set brightness system-wide, so the daytime level is saved in AsyncStorage before the first dim (an OTA reload at 3am can't lose it) and restored at 06:00. Night levels never exceed the daytime one.
- **She can be told, at any hour.** The local brains get `go_to_sleep` / `wake_up` tools (`DeskHandles`); hermes, which has no device tools, sends `[[sleep]]` / `[[wake]]` inside its text instead (and `[[look]]` for the camera, see Vision) — in a proactive Slack message, or in a reply on the hermes or Slack brain (`withDirectives` in FaceScreen). `speakableFromMrkdwn` strips the tokens, so they are never spoken; `src/round/directives.ts` parses them. On the hermes brain the rule rides in `DESK_PREAMBLE`, not only in `hermes/skills/eva-desk-sleep/`: skill-only measured 2/3 sleep and 0/3 wake, each hit 4-5s slower while hermes loaded it; inline is 8/8 at ~1.2s. The skill covers what the preamble can't reach — hermes deciding to sleep her over Slack — and, like any hand-copied hermes skill, only goes live after a gateway restart (the skill list is cached in-process). A sleep request is *pending* until the face goes quiet — landing mid-round would have her asleep while still saying goodnight, and the round ending would wake her straight back up — and a queued goodnight carries `after: 'sleep'` for the same reason. Told-asleep lasts until anything happens; `wake` holds her bright for `WAKE_HOLD_MS`, then the night resumes from there (`requestedPhase`, pure and tested). Both tool results ask for a few closing words: a tool lap that ends silent reads to `useEcho` as a lost answer, and it apologises. `npm run probe:tools` measures the calls.
- Dev overlay → **Sleep** cycles auto / pinned dim / pinned asleep. The overlay itself counts as activity, so close it to see a pinned phase.

Battery (`src/device/`; ASC-45) — level and charging state as a device-health signal, read **without a consent gate** (Michael's decision, Nov 27; unlike the camera, it says nothing about the room):
- `battery.ts` is pure and tested: the reading (`level: null` is unknown, never zero — the simulator reports -1), `describeBattery` for the ear, and `batteryAlert`, which fires on *transitions* only, so an OTA reload of an already-unplugged phone says nothing. Low alerts fire once per crossing of 20% and 10% off the cable. `useBattery` owns the one piece of timing: an unplug must last `UNPLUG_GRACE_MS` before she mentions it, because a nudged connector reads as unplugged for a moment. Alerts ride the proactive queue like a hermes push.
- `expo-battery` is native and lazy-required like `expo-brightness`: a build without it has no `device_battery` tool (absent, not failing) and no watcher. First build to carry it needs an EAS build.
- hermes reads it two ways, since it has no device tools: on the hermes brain, the reading rides as a second system message beside `DESK_PREAMBLE`; over Slack, `[[battery]]` (`directives.ts`, stripped from speech, does not wake the face) gets a reply from `useSlack.tell` as a **new top-level** message — not in the requesting thread, which the desk adopted when mentioned, so hermes' acknowledgement stays silent. `hermes/skills/eva-desk-battery/` documents both.

Room light and screen brightness (`src/device/light.ts`, `screen.ts`, `useLightMeter.ts`; ASC-46) — both read and set **without a consent gate** (Michael's decision, Nov 27):
- **iOS has no ambient light API** (the sensor drives auto-brightness only; expo-sensors' `LightSensor` is Android-only), so the front camera is the light meter: `LightMeter.tsx` mounts an invisible `CameraView` only while measuring, takes one frame with `exif: true`, and the file is deleted unread. `light.ts` (pure, tested) turns EXIF `BrightnessValue` (APEX Bv; EV100 = Bv + 5) into rough lux and a band (dark/dim/lit/bright/daylight). An estimate to within a stop or so — enough for "is it dark", not a lux meter. **Only on demand, never on a timer**: each reading lights the iOS camera indicator, and `shutterSound: false` relies on expo-camera's `AudioServicesDisposeSystemSoundID(1108)` trick, which may not hold on a region with a mandatory shutter sound. It stands down while `camera_look`'s viewfinder holds the camera. A spoken turn may raise the iOS permission dialog; a hermes request never does.
- **A person against the schedule** is `screen.ts`'s `targetLevel`: a requested level holds until the next 22:00 or 06:00 edge, through night talk and dim (so "dim the screen" at 23:00 doesn't get re-brightened to the night's own 10% a minute later), but asleep is always dark. A level set by day simply becomes the daytime level `brightness.ts` saves at 22:00. `useSleep` holds it as `held`; `setScreenBrightness` rides `brightness.ts`'s chain so it can't interleave with a phase flip's save. Not persisted: an OTA reload at night hands the screen back to the schedule.
- Local brains get `screen_brightness`, `set_screen_brightness` (a `level` percent or an `adjust` step — multiplicative, so "dimmer" from 10% isn't black) and `room_light`; every set reports before → after and how long it holds, and logs `desk · screen 60% → 30%`. hermes uses tokens: `[[light]]` and `[[brightness]]` over Slack are answered by `useSlack.tell` like `[[battery]]`; `[[brightness N]]` sets, both in a Slack message and at the end of a hermes-brain reply, and is reported back. The hermes brain gets the level and the *last* light reading (never a fresh one — that would flash the camera every turn) as a per-turn system line that also says how to set it; not in `DESK_PREAMBLE`, to keep that fixed text fixed. `hermes/skills/eva-desk-light/` documents it. `npm run probe:tools` covers the four phrasings, with `camera_look` offered alongside so shadowing would show.

Presence (`src/presence/`, `modules/eva-presence/`; ASC-47) — Eva knows whether someone is at the desk, from a **standing yes** for the camera (the one exception to ask-every-time):
- **Only a number leaves the camera code.** `modules/eva-presence` is a local Expo module (autolinked from `modules/`, so it needs an EAS build): **the camera is not a stream** (ASC-55): every 15s JS calls `look()`, which starts an `AVCaptureSession` on the front camera at 640×480/5fps, waits 1s for exposure to settle (its drift reads as motion), watches 2s, stops the session, and resolves `{faces, motion, frames}`. `faces` is *held* — the largest count Apple Vision's `VNDetectFaceRectanglesRequest` saw in at least half the frames — and `motion` is the share of a 32×24 brightness grid that changed against the first settled frame. Camera-off between looks is the battery saving; throttling the detector alone would not stop the stream. No frame is stored, encoded or sent. `PresenceDetector.swift` has no Expo import, so `xcrun swiftc -typecheck -sdk $(xcrun --sdk iphoneos --show-sdk-path) -target arm64-apple-ios17.0 modules/eva-presence/ios/PresenceDetector.swift` checks it without a build. Vision misses faces lying sideways, so it tries the screen's landscape orientation and then the opposite one.
- **Presence, never identity.** Who it is comes from context. Recognising a face is a possible later ticket (enrolled on device), and the model never identifies anyone from a face.
- `presence.ts` (pure, tested) turns looks into state: one look with a held face *arrives* (a second look would put the greeting 15s late); no face **and no motion** for 45s has *left* (looking at another monitor is zero faces, but rarely stillness); a look with 2+ faces is *busy*, until none has for a minute; nothing for 15 minutes is *away*. `MOTION_THRESHOLD` is applied in JS, so it tunes by OTA against the `[presence] look` dev log. **Motion wakes, only a face greets**: any look with motion or a face *stirs* (`useSleep.stir` — brightens and restarts the quiet clock, but unlike a touch does not end a requested sleep, since the next look would see whoever asked) and clears *away*; a passer-by does not shorten the greeting's away time. Watching starting counts as zero time away, so a launch never greets.
- Behaviours: arriving wakes her (`sleep.poke`) and, after ≥10 min away and outside a 30 min cooldown, she greets by the time of day — never in a busy room, mid-round, or with proactive speech off. *Away* is `useSleep`'s `away` input: asleep and dimmed at any hour, ranked below a round and below "stay up". A busy room only suppresses greetings (Michael, Nov 27); proactive messages still speak.
- **"Stop watching" is handled on the device, before any brain** (`command.ts` + `withWatchCommand` in FaceScreen), so it works on every brain and never depends on a model calling a tool. The choice persists (`eva.presenceEnabled.v1`); "start watching" or the overlay's Presence button turns it back on.
- **Daytime dims too, but only while presence watches**: `DAY_DIM_AFTER_MS` (2 min) of quiet by day is `dim` (never asleep — that is *away*), restored on the next stir. Without presence nothing but a touch would bring the screen back, so with it off days stay bright as before.
- The presence indicator — a small red dot, no label (ASC-53; the open eyes already say she's watching) — shows for as long as presence is polling, in the CAMERA ON badge's spot and colour; the camera may come on at any moment, so it does not blink with each 3s look. Presence pauses while camera_look's viewfinder is up or ASC-46's light meter is measuring, because each needs the front camera to itself, so the badges never show together.

Personality and expressions (`src/personality/`, `src/face/expression.ts`; ASC-59) — Eva has a temperament, and her face says how she feels rather than smiling by default:
- **A personality is six sliders** (`traits.ts`, pure, tested): funny/serious, warm/cool, sassy/gentle, energetic/calm, chatty/terse, curious/matter-of-fact, each 0 … 1. **A preset is only saved slider positions** (`PRESETS`; `chief` is the default and roughly who she always was), so a nudged preset just becomes "custom". Persisted as `eva.personality.v1`. `prompt.ts` turns it into a short manner paragraph — a middle-band slider says nothing, so balance costs no tokens.
- **How it reaches each brain**: the local and realtime brains get `personaWith(PERSONA, …)` = persona + `FACE_RULES` + manner, as the same leading system message — byte-identical until the personality changes, so a change costs one cache miss. Realtime **drops and redials** when the persona it was seeded with goes stale (session is truth). hermes gets `FACE_RULES` + manner as a per-turn system line beside the battery reading, not in `DESK_PREAMBLE`, which stays fixed text with no imports so the probes can load it. Slack can't carry it.
- **"Be more sassy" is handled on the device before any brain** (`command.ts` + `withPersonalityCommand`), like "stop watching": nudges a slider by `NUDGE_STEP`, or picks a preset ("switch to sunny personality", "go back to normal"). Only whole requests aimed at her count — "make this email more concise" stays a question. The overlay's **Personality** button cycles presets.
- **Eva picks her own face** with `[[face amused]]` (optionally `slightly`/`very`) and holds it with `[[pause 1s]]` (default 650ms, capped at 2s — a full second felt long in live testing), in any reply or proactive message, on every brain. `DIRECTIVE_RE` strips both from speech. **They are played against the audio, not the text**: the text of a whole reply usually arrives before its first word plays, so acting on tokens as they streamed in (the first version) landed every face at once and only the last was ever seen. `round/cues.ts` (pure, tested) cuts them out of the stream in order, holding a token split across deltas; `useEcho`'s cue player treats a cue after spoken text as a boundary — end the stream and *drain* it through the consent gate's one-shot `drain` redirect, then change the face or hold the pause (mode `speaking`, voicing off), then open a fresh stream for what follows. Each mid-reply boundary costs a stream start; a cue before any text costs nothing. A Slack reply with cues is fed through the same player as one delta, and a proactive message carries its raw text as `ProactiveItem.cued` (the spoken `text` has the tokens flattened away) and is announced through it. Each round starts from the resting face. The overlay's **Expression** button tries each in turn.
- **An expression is a blend over the mode, not a mode** — the same idea as asleep's `sleepK`: `eyeGeo`'s `exprName`/`exprK` multiply the mode's own scale and glow (so speaking's pulse survives inside a smile) on idle, resting and speaking only; listening, thinking and alert keep their poses. The first nine poses are the static part of a design pose (pleased, thinking, listening, alert, confused); `concerned` and the thirteen added on Michael's ask (excited … sideeye) are invented and need a pass in the design file. Those use two things the design never had: per-eye rotation (`EyeGeo.r`, mirrored by side — outer corners down for sad, inner down for angry/determined) and `EYE_CORNERS_LID`, the crescent upside down, for bored/sleepy/annoyed/side-eye. The mouth only takes an expression's shape (smile, oh, confused's K) when still and more than half worn (`EXPRESSION_MOUTH_AT`). Personality scales intensity (`expressiveness`: energetic and warm emote bigger).
- **There is no default smile.** The post-reply beat that used to be `'pleased'` is the `'resting'` mode: drawn like idle wearing the reply's expression, and a separate mode only because it must not count as idle (wake watcher, realtime release). After the reply a picked expression is held `EXPRESSION_HOLD_MS` once idle, then eases back to `restingExpression(traits)` — neutral for most presets, a soft smile only for sunny, a faint raised brow for sassy. The `'pleased'` mode still exists for the overlay.
- **Listening is a waiting look** (also invented): head tilted `WAITING_TILT_DEG` (the other way from confused — expectant, not lost), a slow glance instead of the quick sway, a breathing glow, and it blinks. **A reply ending in a question** floats a "?" up beside the right eye as she stops speaking (`question.ts` pure and tested, `QuestionMark.tsx`).
- Not done yet: idle animation and blink rate don't vary by personality, and voice/pacing is unchanged.

OTA updates (`src/updates/`) — the preview build applies `eas update` bundles without a relaunch:
- expo-updates alone checks at launch and applies on the *next* launch, and Eva launches once a week. `useOtaUpdates` checks hourly and reloads into a downloaded update — including one the launch-time check fetched — once `reloadBlocker` (pure, tested) clears.
- A reload restarts all JS, so the blockers are a list of what lives only in memory: errands in flight (an `ask_other_half` answer would vanish silently), the proactive backlog, a busy face, the open overlay, and two quiet minutes after idle (covers a re-wake and the realtime socket's 45s grace).
- The overlay's "Check for update" reloads at once — the person pressing it is the speech check — but still defers over an errand, which nobody at the desk can see. `Updates.isEnabled` is false in dev builds, so everything is a no-op there.
- Publish with `eas update --channel preview --environment preview`; without `--environment` the bundle has no keys.

## Wallboard (`wallboard/`)

A separate Node project, not device code: the family's kitchen board on an Echo Show 15 (Silk), hosted on the exe.dev VM `eva-board.exe.xyz`. It has its own `package.json`, tests (`node:test`) and deploy (`npm run deploy` from inside it). Root jest, tsc and Metro all exclude it. See `wallboard/README.md` for the push API hermes writes to.

## Constraints

- Orientation is locked landscape in `app.json`; keep-awake is on in `App.tsx`. Don't add portrait handling.
- Eye separation is fixed wide (300px gap) and the side column defaults to visible — both explicit product decisions; don't resurrect the toggles from the design doc.
- Native module changes (new Expo packages with native code) require a new EAS **preview** build (`--profile preview`) on the dedicated iPhone; JS-only changes ship by `eas update`. The phone runs the preview build, not a dev client — don't build the `development` profile unless explicitly asked.
